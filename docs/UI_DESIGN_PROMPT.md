# KnowRAG Vue3 UI 设计提示词

请你为 **KnowRAG：RAG 个人知识库问答系统** 设计一个 Vue3 + Vite + TypeScript 的 Web 应用 UI。

整体风格参考 DeepSeek 网页版的产品气质：简洁、现代、留白充足、浅色为主、圆角柔和、层次清晰，并带有轻微磨砂玻璃质感。注意：只是参考这种干净、克制、高级的视觉方向，不要照搬 DeepSeek 的品牌、Logo、文案或具体布局。

## 产品定位

KnowRAG 是一个生产级个人知识库问答系统，用户可以上传文档、配置不同 LLM / Embedding / Reranker 模型，并基于自己的知识库进行流式问答。UI 应该像一个长期使用的效率工具，而不是营销官网。

## 技术栈

- Vue3
- Vite
- TypeScript
- Pinia
- Vue Router
- Element Plus 或 Ant Design Vue
- Fetch + ReadableStream 用于流式问答
- markdown-it + DOMPurify 用于 Markdown 安全渲染

## 整体视觉风格

- 主色调：浅色、低饱和、干净现代。
- 背景：接近白色或极浅灰，可以有非常轻微的冷色渐变，但不要花哨。
- 质感：核心面板可使用轻微 `backdrop-filter: blur(...)` 的磨砂玻璃效果。
- 圆角：柔和但克制，常规卡片和输入框建议 12-18px。
- 阴影：非常轻，避免厚重投影。
- 边框：使用浅灰透明边框，强调精致感。
- 字体：系统字体优先，中文显示清晰，字号层级克制。
- 留白：页面要呼吸感强，避免密集堆叠。
- 图标：使用 lucide 或 UI 框架图标，线性、轻量。
- 动效：微交互即可，如 hover、focus、流式回答出现，不要夸张动画。

## 应用布局

设计为典型 AI Chat + Knowledge Base 工作台：

1. 左侧侧边栏
   - 顶部展示 KnowRAG 名称。
   - 新建会话按钮。
   - 会话历史列表。
   - 文档管理入口。
   - 模型设置入口。
   - 底部展示当前用户、退出登录。

2. 中间主工作区
   - 聊天问答主界面。
   - 空状态展示欢迎语和几个问题示例。
   - 消息气泡简洁、留白充分。
   - 用户消息靠右或以轻色块区分。
   - AI 消息以正文阅读体验为主，不要过度卡片化。
   - 支持 Markdown、代码块、列表。
   - AI 回答底部展示引用来源。

3. 底部输入区
   - 固定在主区底部。
   - 大圆角输入框，支持多行输入。
   - 发送按钮使用图标。
   - 附近展示当前模型、知识库开关、检索状态。

4. 右侧可选信息面板
   - 展示引用来源、当前知识库索引状态、trace_id、检索耗时。
   - 可以折叠，不要占用过多空间。

## 页面清单

请设计以下页面：

### 1. 登录页

- 简洁居中布局。
- 左上或顶部展示 KnowRAG。
- 登录卡片使用轻微磨砂玻璃质感。
- 包含用户名、密码、登录按钮、注册入口。
- 不要做营销式 hero 大图。

### 2. 注册页

- 与登录页风格一致。
- 包含用户名、邮箱、密码、确认密码。
- 表单校验状态清晰。

### 3. 聊天页

核心页面，需要重点设计。

必须包含：

- 左侧会话列表。
- 中间聊天流。
- 底部输入框。
- 知识库开关。
- 当前 LLM 模型显示。
- 流式生成状态。
- 引用来源列表。
- 空状态示例问题。

交互状态：

- 正在生成回答。
- 回答失败。
- 当前知识库索引不可用。
- 没有上传任何文档。

### 4. 文档管理页

必须包含：

- 上传区域。
- 文档列表。
- 文件名、大小、上传时间、索引状态。
- 摄取任务进度条。
- 失败原因展示。
- 重建索引按钮。
- 当前 Embedding 模型和索引版本展示。

状态：

- 空文档。
- 上传中。
- 解析中。
- 索引成功。
- 索引失败。
- 索引 stale，需要重建。

### 5. 模型设置页

必须包含：

- LLM provider：DeepSeek / Qwen。
- LLM API Key 输入框，支持脱敏展示和替换。
- LLM base_url、model、temperature、max_tokens。
- Embedding provider：local / qwen。
- Embedding model / local path。
- Reranker provider：local / qwen。
- Reranker model / local path。
- 保存按钮。
- 测试连接按钮。
- 如果 Embedding 变化，提示“需要重建知识库索引”。

设计要求：

- 设置项分组清晰。
- 不要把所有表单堆成一大片。
- 每组设置像轻量 section，不要嵌套过多卡片。

### 6. 会话历史页

- 列表展示历史会话。
- 支持搜索、删除、继续会话。
- 显示最近更新时间。

## 颜色建议

可以使用类似下面的色彩方向，但不必完全一致：

- 背景：`#F7F8FA`
- 主面板：`rgba(255, 255, 255, 0.72)`
- 边框：`rgba(20, 24, 35, 0.08)`
- 主要文字：`#18202F`
- 次要文字：`#6B7280`
- 主色：`#4F7DFF` 或更克制的蓝色
- 成功：`#16A34A`
- 警告：`#D97706`
- 错误：`#DC2626`

避免：

- 大面积深色背景。
- 大面积紫色渐变。
- 过度拟物。
- 营销官网式 hero。
- 复杂装饰图形。

## 交互细节

- 所有按钮、输入框、列表项需要 hover / active / disabled 状态。
- 流式输出时，AI 消息应逐步追加文本。
- 发送中输入框可以禁用或支持停止生成按钮。
- 上传任务应实时展示进度。
- 保存模型配置成功后给出轻量 Toast。
- Embedding 配置变化时，用醒目的但不刺眼的提示提醒用户重建索引。
- 错误提示要具体，比如“当前知识库索引不可用，请先重建索引”，不要只写“请求失败”。

## 响应式要求

- 桌面端：左侧栏 + 主聊天区 + 可选右侧信息面板。
- 平板端：右侧信息面板默认折叠。
- 移动端：侧边栏变为抽屉，输入框固定底部。
- 所有文本不能溢出容器。
- 表格在窄屏下可切换为列表卡片。

## 输出要求

请输出：

1. UI 设计说明。
2. 页面结构设计。
3. 组件拆分方案。
4. 推荐路由结构。
5. 推荐 Pinia store 结构。
6. 关键页面的 Vue3 + TypeScript 示例代码。
7. 全局 CSS / design tokens。
8. 聊天页、文档管理页、模型设置页的核心实现示例。

最终效果应当像一个真正能长期使用的 AI 知识库工作台：安静、清晰、轻盈、可信赖。
